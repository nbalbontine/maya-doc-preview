3. Surface detail

TP-01 — Assist standalone chat

  • Where: Trimble Assist, opened directly (not inside another product).
  • Persona sees: a chat interface; can ask across any project the user can access.
  • Persona can do: ask questions; receive evidence reports and link-outs.
  • Output: evidence report (TP-07), link-outs (TP-12).
  • Workflows: WF-09
  • Confirmed against: system-context C10.

TP-02 — Assist embedded in ProjectSight / Connect

  • Where: a chat panel inside ProjectSight Web or Trimble Connect.
  • Persona sees: the same chat, scoped to the open project.
  • Persona can do: ask questions relevant to records in that product.
  • Output: evidence report (TP-07), link-outs (TP-12), heat-map overlays where the viewer is reachable from this context.
  • Workflows: WF-01, WF-04, WF-05, WF-08, WF-09
  • Confirmed against: system-context C10; embedding pattern moving from iframes to modular web SDK components (unconfirmed timeline — UB-01).

TP-03 — Assist embedded in the Maya / Connect viewer

  • Where: a chat panel inside the 3D/360 viewer.
  • Persona sees: chat plus the viewer's own controls (split screen, mini-map, calendar).
  • Persona can do: ask questions; the agent can control the viewer (per WS-D2, WS-SH).
  • Output: heat-map overlays (TP-04, TP-05, TP-06), split-screen pairs (TP-08), evidence report (TP-07).
  • Workflows: WF-02, WF-03, WF-04, WF-06, WF-07, WF-08
  • Confirmed against: system-context C11 (prototype).

TP-04 — Change heat-map overlay

  • Where: floor plan in the Maya/Connect viewer.
  • Persona sees: zones coloured by change intensity (major, moderate, none) between two dates.
  • Persona can do: click a zone to open the before/after pair (TP-08).
  • Output: none further; leads to TP-08.
  • Workflows: WF-02
  • Confirmed against: system-context C11, C15 (prototype; deterministic per WS-SH).

TP-05 — Coverage overlay

  • Where: floor plan in the Maya/Connect viewer.
  • Persona sees: captured versus not-captured areas for a chosen period.
  • Persona can do: identify where to send the next walk.
  • Output: list of uncovered areas with days since last capture (part of TP-07).
  • Workflows: WF-03
  • Confirmed against: system-context C15 (prototype); the overlay itself is not yet built — UB-02.

TP-06 — Progress-to-plan heat-map overlay

  • Where: floor plan in the Maya/Connect viewer.
  • Persona sees: zones coloured ahead / on / behind plan.
  • Persona can do: click through to the evidence for a zone.
  • Output: evidence report (TP-07).
  • Workflows: WF-04
  • Confirmed against: system-context C11, C15; depends on a schedule source not yet connected — UB-03.

TP-07 — Evidence report

  • Where: rendered inside whichever Assist surface (TP-01, TP-02, TP-03, TP-10) the question came from.
  • Persona sees: the answer, dated images, coordinates, source-record references, and — when Maya cannot answer — the decline and path to yes.
  • Persona can do: accept, reject, ask a follow-up, rate the answer (TP-14), open a link-out (TP-12).
  • Output: the persona's decision downstream (e.g. closing a record in TP-12).
  • Workflows: WF-01, WF-02, WF-05, WF-06, WF-07, WF-08, WF-10
  • Confirmed against: unconfirmed — this is Assist's response format, and Assist renders text-heavy today (WS-D3); the visual, evidence-first shape is a requirement on Assist, not yet built — UB-04.

TP-08 — Split-screen before/after image pair

  • Where: Connect 3D viewer.
  • Persona sees: two stations, same location, different dates, side by side.
  • Persona can do: compare visually; zoom; annotate (v1 capability).
  • Output: none; a viewing surface.
  • Workflows: WF-02, WF-06, WF-08
  • Confirmed against: system-context C05 (V1-PRD: live v1 feature).

TP-09 — Scheduled coverage notification

  • Where: email or an Assist notification, sent after a capture finishes processing.
  • Persona sees: a coverage summary for the walk just uploaded.
  • Persona can do: open TP-05 for detail.
  • Output: none.
  • Workflows: WF-03
  • Confirmed against: unconfirmed — no scheduled/headless trigger exists yet for this — UB-05.

TP-10 — Assist embedded in SKIT

  • Where: SKIT support tool.
  • Persona sees: chat scoped to one customer's access and processing records.
  • Persona can do: ask why a capture failed; escalate with the evidence attached.
  • Output: evidence report (TP-07).
  • Workflows: WF-10
  • Confirmed against: system-context C16 (Assist-in-SKIT on Agent Studio staging).

TP-11 — Maya MCP as agent-to-agent peer

  • Where: Agent Studio; another agent (APE, or an external agent such as an OpenSpace-style peer) calls Maya's MCP tools.
  • Persona sees: nothing directly; the result surfaces inside the calling agent's own front end.
  • Persona can do: n/a — this is agent-to-agent.
  • Output: structured data back to the calling agent.
  • Workflows: WF-01 (demoed resolving an RFI and closing a punch item via MCP, WS-D1/WS-D2), WF-04 (APE as schedule peer)
  • Confirmed against: system-context C06 (prototype), C09; authorization pattern for this path is one of the open architecture questions (AQ-01, AQ-02).

TP-12 — Link-out to the source record

  • Where: ProjectSight or Connect, opened from an evidence report.
  • Persona sees: the actual RFI, punch item, BCF topic or model element.
  • Persona can do: close, approve or edit — in the source product, by the person.
  • Output: the source-system change, made by the person.
  • Workflows: WF-01, WF-06, WF-07, WF-08
  • Confirmed against: system-context C13, C14 (source system wins, D-06).

TP-13 — Exportable evidence pack

  • Where: from Assist, attachable to a payment application.
  • Persona sees: a document or export of dated images per schedule-of-values line.
  • Persona can do: attach it where the payment application is prepared.
  • Output: a file or export.
  • Workflows: WF-05
  • Confirmed against: unconfirmed — no export format exists, and whether it lands in Trimble Pay or a generic export is undecided — UB-06.

TP-14 — In-app feedback control

  • Where: attached to every Maya answer, in every embed.
  • Persona sees: a way to rate or flag the answer, screenshot and comment.
  • Persona can do: submit feedback; it is captured with DOM/screenshot/commit context and routed to Jira.
  • Output: a feedback record.
  • Workflows: every workflow
  • Confirmed against: system-context C20 (planned, mandated for every build, WS-D1 D-08).
